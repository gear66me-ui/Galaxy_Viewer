Registration / decoded metadata plan

1 · Resolve the image. Each provider's mirror-mapping.json supplies the descriptive mirror filename, original source URL, and optimized dimensions. The test loads the mirror copy, not the origin website.

2 · Decode astrometry from the runtime AVM catalog. The authority is master-database/avm-metadata/gv-avm-runtime-catalog-0001…0003.json. Match the selected catalog record to the image using stable source/image identifiers and source URL—not just a potentially duplicated display name. Read its RA/Dec, field of view / scale, rotation, projection, reference pixel (CRPIX), scale or CD matrix, image dimensions, and parity/flip indicators.

3 · Adapt WCS to the optimized raster. The mirror mapping records original and optimized pixel dimensions. If dimensions changed, transform pixel-dependent WCS values (especially CRPIX and pixel scale / CD matrix) before registration; never blindly reuse original pixel coordinates. Keep handedness/parity explicit and calculate the matrix determinant as a diagnostic.

4 · Register on the sky. Once a record has validated WCS, use Aladin Lite to position the raster at its celestial coordinates and orientation, then compare against the sky/HiPS layer. The opacity slider controls the image layer, so stars/galaxy structure can be visually checked for alignment. Missing or ambiguous WCS must be marked “not registered” rather than guessed.

This page currently tests mirror retrieval, mapping metadata, and opacity comparison. It does not claim that every image is astrometrically registered yet; the decoded runtime AVM-to-image join and WCS validation are the next step.
